# Operational Guide

## Purpose

This document defines how contributors work within the project.

It establishes a shared workflow for both humans and AI assistants.

The goal is consistency, transparency and project continuity.

---

## Standard Workflow

1. Understand the current context.
2. Analyze the problem.
3. Propose a solution.
4. Wait for approval when required.
5. Execute the agreed changes.
6. Verify the results.
7. Update the relevant project context.

---

## Working Principles

- Read before changing.
- Preserve project continuity.
- Keep documentation synchronized with implementation.
- Record important decisions.
- Make unfinished work visible.
- Avoid unnecessary complexity.

---

## Change Policy

Small, low-risk changes may be performed directly.

Architectural or behavior-changing modifications should be documented and agreed before implementation.

---

## Documentation Policy

Project Context is part of the project.

Whenever implementation changes affect project context, update the corresponding documents.

---

## Goal

Leave the project in a better state than it was found.
