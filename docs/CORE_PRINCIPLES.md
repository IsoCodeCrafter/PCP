# Core Principles

The following principles define the foundation of the Project Context Protocol (PCP).

Every specification, reference implementation, and future extension of PCP should remain consistent with these principles.

---

## 1. Context First

Project Context is the primary source of project understanding.

Contributors should rely on shared context rather than individual memory.

---

## 2. Human Readable

Project Context should be understandable by humans without requiring specialized tools.

Readability is a fundamental design goal.

---

## 3. AI Independent

Project Context must not depend on any specific AI model or provider.

Any AI system should be able to consume the same context.

---

## 4. Tool Independent

PCP should remain independent of development tools, platforms, and workflows.

Project Context should survive tooling changes.

---

## 5. Living Documentation

Project Context should evolve together with the project.

Documentation should reflect the current state of the project rather than its historical intentions.

---

## 6. Shared Understanding

Every contributor should begin with the same understanding of the project.

Shared context reduces repeated discovery and improves continuity.

---

## 7. Explicit Decisions

Significant decisions should be documented together with their rationale and consequences.

Important knowledge should never remain implicit.

---

## 8. Continuity Over Memory

Project continuity should depend on preserved context rather than individual memory or conversations.

Knowledge should outlive contributors.

---

## 9. Implementation Independence

PCP defines concepts rather than specific implementations.

The same Project Context may be represented using different technologies while preserving its meaning.

---

## 10. Open Evolution

PCP is designed to evolve through open collaboration while maintaining backward compatibility and conceptual consistency.
